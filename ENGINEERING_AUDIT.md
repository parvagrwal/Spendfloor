## System and trust boundaries

`policy/` encodes a 122-byte SHA-256 preimage, provides a decision oracle and Ollama-assisted English drafts. `agent/` turns model output into EIP-712 intents or partially signed legacy Solana transactions. `relay/` is an in-process gas sponsor, **not** an authenticated network service. `sdk/` supplies signing, RPC, receipts, local file custody and setup/spike scripts. `cli/` reads chain state and operates owner keys. `conformance/` runs stateful scenarios; some scripts spend on public testnets. `rebalance-bot/` is a manifest only. `scripts/raw/` and early T06/T07 scripts are experiments, not deployment automation. `deployments/` and `sdk/addresses.json` are public snapshots. `docs/` and `evidence/` contain historical results, including failures. `.github/workflows/ci.yml` runs Foundry and an optional Socket scan; missing credentials skip that scan.

Authoritative storage is the Solidity vault + six-decimal ERC20 and Anchor program + classic SPL mint/accounts. One owner and one agent per vault, singleton policy PDA per Solana program. Owner-only administration; spent counters change with the transfer in the same chain transaction. EVM binds signatures to domain, deadline and nonce. Solana signs the full transaction; exact message duplication differs from re-signing with a fresh blockhash. Caps and failure precedence are local to each chain, not a shared allowance. Cross-chain commands cannot commit atomically. No SQL, RLS, password/session cookies, HTML rendering, uploads or HTTP tenants to test. On-chain account locks/transaction rollback, PDA constraints and contract authorization serve in place of database transactions and access policies.

## Implementation order / release gates

1. Contain signer and filesystem boundaries (R1–2); prove rejection before broadcast and no overwrite.
2. Make state reads and receipts fail safely, remove unsafe dependencies and bound resources (R3, R5–7); run negative and positive tests and cold install.
3. Gate TS and EVM builds in CI, align configs and document bootstrap/recovery limitations (R4, R8–9). Do not change chain storage layout or transact against an existing deployment.
4. Re-run regressions, scans, and assess readiness independently. No real-funds release without both native suites, audited bootstrap, independent verifier, operational custody and incident drills.
