The client conversation

Show the hard part first.

A useful agent-payment system must refuse an unsafe instruction and still permit a legitimate payment. This demonstration makes both outcomes inspectable.

01 / Prompt

The agent can be manipulated.

Assume a prompt injection convinces the agent to create a 50 SFUSD payment to an attacker.

02 / Boundary

The relay has no policy authority.

It can pay gas and submit a signed intent, but cannot move vault funds around the checks.

03 / Outcome

The vault is the final decision.

The recipient check fails before funds move. A merchant payment that fits the same policy is accepted.

Where the rules live

What is real, what is represented.

EVM vault

evm/src/SpendFloorVault.sol verifies an EIP-712 agent intent, nonce/deadline transport checks, policy state, caps, recipient, then transfers.

Solana program

solana/programs/spendfloor/src/lib.rs requires the agent co-signature and uses the policy PDA to transfer only after its mirrored decision.

This page

A deterministic, read-only representation. It does not compile contracts, use a wallet, make RPC writes, or claim that sandbox runs are on-chain.

Policy authoring guard

A draft may propose. It cannot quietly widen.

The repository’s policy diff classifies a draft as looser if it increases money, adds recipients, replenishes faster, or extends a bounded expiry. Explore that gate safely here.

Testnet only

Base Sepolia and Solana devnet use a test token. This is not a production funds or mainnet demonstration.
